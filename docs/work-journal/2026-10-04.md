# 2026-10-04

## Last night's closeout, and #200 on the board

The morning began with the closeout of 10-03's evening, committed as
`d89908f` after a read (the roadmap's ERDP item, the journal's last section
and its index row, and the two blind instruments of the evening in their
postmortem). Then the one board round the closeout left open: card and
stick staged together from `main` at `d89908f`, which is #200's kernel and
one docs commit, so the boot names `build d89908f1d0ab debug` and the ERDP
order is the only variable. Yesterday's capture was moved to `scratch/`
first, so `screenlog.0` holds this round and nothing older.

A small scare in the staging, settled before the boot: the card's
`BOOTAA64.EFI` differed from `build/esp`'s, because `make stick` rebuilds
the kernel (`build.rs` reruns every build). A rebuild with nothing changed
differs in ten bytes, one in the PE header and a nine-byte run near the end,
the fields a link restamps, so the code and the build line are the same.

Hans booted it twice. Both boots reached the shell, mounted the stick's
exFAT over SuperSpeed port 3, and ran a session over the serial console
(`ls`, `ls -l`, `cat etc/passwd`, `man`, `chello`, `bootid`, `shutdown`),
each ending in a PSCI power-off. No fault, no command timeout, no `Host
System Error`. ERDP before ERSTBA costs nothing visible on the board.

The capture had one difference from yesterday's: no keyboard behind the
hub. It was not plugged in. Hans now works the Pi over the serial console
alone, with no USB keyboard and no display, since both were shown working
on 10-03; he will plug them in now and then, and report if either stops.
So from here a boot that says `keyboard not available` is the expected
line, and the hub path is exercised only when he plugs one in.
