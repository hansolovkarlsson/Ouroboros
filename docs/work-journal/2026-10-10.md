# 2026-10-10

## #253 merged, and the `Ozq` check made to fail (#254)

#253 merged in the morning after a low review found nothing. Hans then asked
for the check it had left blind. The question was why `test-kbd-mode`'s Esc
check could not fail even with E1 and E2 both removed, which a reading of the
queue said it should. The transcript of that run answered it: between the
interrupt and `Ozq` the rig typed the shell's next command, `readkey spin 100
keep`, and under the day-old `keyseq` its `r` ends any open Esc. The bytes
the check meant to probe were never the first after the interrupt. On main
the same check had been masked by E2 instead, which closes the Esc 40 ms
after it is read, long before the next key is.

The fix was to make `Ozq` the shell's next line. Run three ways: green on the
tree, red with E1 and E2 removed together (the shell ran `q`), green with E1
alone removed. That last result is not a weakness of the check but a fact
about the system: E1 matters only for a key read within E2's interval of the
Esc, and the shell's wake and its `wait: interrupted` line take longer, so no
rig can see E1 alone. Its host test is the check for it, which
`test-kbd-cut`'s check 3 already said for the kill path.

## The `/net` poll check that cannot be run

Hans asked for the first item of the standup's "unchecked by any rig" list:
`poll` on a `/net` file answering `POLLERR`. Reading `file.c` before writing
the rig answered it. `open` refuses the `/net` binding at `resolve_target`
(ENOSYS, the same refusal the console binding gets), so a C program cannot
hold a `/net` fd, every open fd is fsd's or a remote mount's, and `poll`'s
`POLLERR` branch is unreachable. A check of it cannot fail, and deleting
the branch would change nothing any run could see. The claim that a `/net`
file "is `POLLERR`" stood in `poll.h`, `file.c`, the changelog, the source
map and the gap analysis, a sentence true of no observable run since #240.

What went in instead is the smallest thing that makes the claim checkable:
`cpoll timing` opens `/net/ip` and `/net/tcp/clone` after the rig's
`mount -n /net`, asserted as its own step, and prints each errno, and
`make test-cpoll` requires ENOSYS for both (a high review of #256 added the
connection file, the file a program would poll, since an `open` that
learned only `/net/tcp` would have left the status file refused and the
tripwire green; it also had the verdict quote what the guest printed). The branch stays as the
default an `open` that learns `/net` would fall into, which is safer than
a "ready" whose read blocks; the day that happens, the tripwire fails and
the real check is owed with it. The five records now say that. The lesson
is the standup's own, read the other way round: before writing a check,
ask whether the input it needs can be made at all.

## The ISO key check that no rig can run

The next item from the same list, the ISO keyboard's backslash key at HID
0x32, which `xhci.rs` maps as the US key so Ctrl+\ works from it. The rig's
docstring already said QEMU cannot send it, and before accepting that I
checked it two ways. keycodemapdb, QEMU's keycode table, lists the US key
(USB 49) and the ISO key (USB 50) under one QEMU key code, `backslash`, and
its generator takes whichever row it reads last, so the table alone did not
say which. A throwaway build settled it: 0x32 made to type `#`, then
`sendkey backslash` into `readkey one` gave 92 and `shift-backslash` 124,
the US key's bytes, and `less`, the key beside left Shift, nothing. The
build was discarded and the image rebuilt from the restored tree. PS/2
gives both positions one scancode, so `prlctl` cannot press it either, and
the kernel has no host tests. The check is therefore a by-hand row in the
Parallels matrix, A7, and needs an ISO keyboard; an ANSI one has neither
key. The roadmap says so, and that the mapping rests on the HID usage table
until a hardware session types it. Two items from the list, two checks that
could not be run as asked, each for a different reason: the first because
the input cannot exist on this system, the second because no instrument
here can make it.

## Multi-core set as the next arc

Hans asked when multi-core would be wise to start. The answer from the
records: the plan now, since no arc is mid-flight and the roadmap asks for
a plan before code; the kernel work after three tails that are cheaper to
settle on one core than to redo under a lock (FP/SIMD eager or lazy, the
tick's four jobs with four tick streams, task 0's entry past the
trampolines); and the cost not in starting the cores but in replacing the
single-core argument, one sentence that covers about 120 statics. Hans set
it as the arc for the coming week, while DevTools's C compiler is being
finished. `docs/roadmap/roadmap-smp.md` is the plan: the census, the
inventory in five classes by owner (boot-only, per-core, scheduler-owned,
device-owned, console and keyboard) with what step 4 does to each, the
three decisions, the design of a core's start and of scheduling, five steps
each with a check that can fail, a size that says the week covers steps 0
to 3, and the risks. Step 0's deliverable is a check in `make test` that
every static in the tree is in the inventory by name, so the static that
falsifies the argument on another day cannot be added silently.

## Step 0 of multi-core: the inventory as a check

The plan merged (#258), Hans said "then step 0". `scripts/check-statics.py`
lists every `static` in `kernel/src`, indented ones included, as
`module::NAME`, and requires each to appear in exactly one class row of the
plan's inventory table, failing with the name for a static in no row, in
two, or gone from the tree. Writing it changed the table: the rows had
named groups by count ("the eleven `earlyfault` cells", "seventeen DMA
statics"), which a check cannot read, so every one of the 119 is now named,
and three moved class while being named (`gicv3::GICD_BASE`,
`exceptions::NET_INTID` and the two storage boot flags are written once at
boot, so class A; the syscall staging buffers become per-core, so class B).
Three controls each turned it red with the name: a misspelt entry, a static
appended to `power.rs`, a name placed in a second row. It runs in
`make test` and as `make check-statics`. 119 statics, A 23, B 9, C 34,
D 44, E 9, counted by the check and not here.

## What the session was made of

Three PRs across the evening of 10-09 and the morning of 10-10, each merged on
Hans's word. The largest, #253, went through two high reviews and a low one,
and its design changed between them: a cost I had called acceptable looked
different once a reviewer spelled it out as a login that fails. The lesson I
would keep is about controls: a change that widens what the system accepts
silently blinds every check whose control relied on the old refusal, and the
remedy is to choose the input the new rule still treats specially.
