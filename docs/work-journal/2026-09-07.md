## 2026-09-07: an audit of the segment, and four moves that emptied the top of `docs/`

No code landed today. The day was a `/project-audit` of the segment since
v0.18.1 in the morning, and then a reorganization of `docs/` that the audit's
own reading suggested, done as four pull requests (#114 to #117) and merged in
order. It is the first day recorded in this directory rather than in the
single `journal.md`, and it is the day that made the directory.

**The audit.** The segment v0.18.1 to `c6924d0` was 37 commits, 23 merged pull
requests, twelve tasks by the audit's grouping, and 81 files changed. Its
kernel, shell, `netd` and `fsd` diffs read clean. The two real defects it found
were both in `libc/src/file.c`, which landed on 09-05 under one `medium` review
pass: a client-side error code placed one step below `FS_ERR_MIN`, so the code
written to read it (`cremote.c`'s `why()`) prints "no error recorded" for a
path over 255 bytes or a ninth open; and a status variable whose comment says
"cleared on success" and which nothing ever clears. Both are the same shape as
[`true-when-written-postmortem.md`](../postmortems/true-when-written-postmortem.md):
a constant outside the predicate written to read it, and a comment stating a
guarantee no line enforces. The lesson the standup carries is where they were:
the kernel and shell changes had eight review rounds on 09-06 and were clean;
`file.c` had one, and that is where the bugs were. Review effort tracked where
the risk felt highest, not where the code was least looked at.

The audit also found seven open items that had lived only in the standup's
"Carried" line since 09-03, a file the next closeout overwrites. Each was
checked against the tree before it was written down (`crt0.c` really does call
`main(void)`; the bad-fid arm really does answer bare `FS_ERROR`), and they are
now entries at the end of `ROADMAP.md`'s open gaps (#116). The standup's
"Carried" line is empty for the first time since it existed.

**The moves.** The top of `docs/` held 32 markdown files. It now holds 15. The
journal became [`work-journal/`](README.md), one file per day with the entries
inside a day reversed into the order they were written (#114); the 29
postmortems moved into `postmortems/` (#115); and the eight roadmap sub-plans,
four testing guides and five research notes moved into `roadmap/`, `testing/`
and `research/` (#117). `ROADMAP.md` and `roadmap-completed.md` stayed at the
root on purpose: they are the two halves of the ledger the closeout finds by
role, not plans, and four site pages link the roadmap by URL. Filenames were
kept everywhere, so `roadmap/roadmap-cluster.md` doubles a word; that is the
price of 400 references staying within reach of a rule, and of every memory
note and sentence that names a file by name staying true.

Each move was built the same way, and the shape is worth recording because it
is what made a 70-file diff reviewable. Commit one is a pure `git mv` plus the
site checker's manifest paths, so every blob hash is preserved and
`check-site` is green on that commit alone. Commit two is the reference
rewrite, computed by rule rather than found by grep: inside a moved file, a
relative link to anything that is not a sibling gains `../`; from the root, a
bare name gains its folder; from one level down, `../x.md` becomes
`../folder/x.md`; code comments, scripts, the Makefile and the site's GitHub
links take the `docs/folder/` form. The prose that names a location in a
sentence rather than a path ("the postmortems under `docs/`", six places) was
done by hand, because no rule finds a sentence. Commit three re-stamps the
site pages whose sources changed only in link paths, after reading each page
against its source. Two checks ran after every rewrite: no relative link under
`docs/` outside the archive points at a missing file, and no path-bearing
reference to the old location remains outside `docs/archive/`, which was left
as written on purpose, since an archive is for text that was true when written.

**Three things went wrong, none of them shipped.** The audit estimated eight
site pages would need re-stamping after the postmortem move; it was two. The
estimate came from a grep that counted outward links in every postmortem,
including the nineteen the site does not abridge. A pathspec `git stash` of
the roadmap edit, taken while `journal.md`'s deletion was staged on the same
branch, carried that staged deletion with it, so the first cut of #116 would
have deleted the journal with nothing in its place. It was caught by reading
the commit's `--stat` before reporting the PR, amended, and pushed with lease.
And BSD `sed` refused the `(a|b)` groups the rewrite rules used, twice, and
each time the fallback was the same Python that had done the rest. Both traps
are in
[`blind-instruments-postmortem.md`](../postmortems/blind-instruments-postmortem.md)
now, under today's date.

**The stacked merge worked as its postmortem says.** #115 was based on #114's
branch so its diff showed only the move. #114 was squash-merged without
deleting its branch, #115 was retargeted to `main` with `gh pr edit --base`,
rebased with `git rebase --onto origin/main docs/work-journal`, checked with a
local `merge-tree`, pushed with lease, and merged once GitHub had recomputed
mergeability. That is the mechanic
[`review-and-split-postmortem.md`](../postmortems/review-and-split-postmortem.md)
records from the day it cost a PR its number, run deliberately this time.

syscalls 67 and 68, the changed `DELEGATE` answer and the moved error floor.
The two `file.c` bugs are unfixed. Three counts are still false in the records:

62), `CLAUDE.md`'s `make test` paragraph, and three `libc` files missing from
`source-map.md`. The postmortem count in `CLAUDE.md`, which disagreed with
itself since 09-03, was fixed as a side effect of #115 rewriting the line.
