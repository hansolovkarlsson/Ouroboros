# 2026-10-05

## Last night's closeout committed, and PORTSC a type of its own (#209)

The day began with the closeout of 10-04's late night, committed as
`30422e8` after a read and pushed once `make test` was green (175 host
tests). No handoff was open.

The first item taken was the one #207's reviews had left: PORTSC was a
`reg::Whole32`, the same type as the doorbells, so a port function would
take a doorbell, and every write had to pass through `portsc_preserve` by
convention, or it wrote PED back (disabling the port) and cleared change
bits still pending. The same opt-in shape #207 removed for RsvdP. The first
cut gave PORTSC a handle of its own, `reg::PortStatus`, whose write read
the port itself and masked PED and the change bits, taking the bits to set
and the change bits to clear as two arguments. Three spellings were shown
not to compile by mutation (a one-value write, a doorbell for a port, a
hand-built handle), and a merge writing the change bits back failed the
new build-time asserts.

Its review (`/code-review high`, seven findings) showed the first cut had
kept the very shape it was meant to end, on other bits. The mask still
worked by exclusion: everything but PED and the change bits went back as
read, so PR, which is RW1S, would start a second reset if written while one
was running, and a RsvdZ bit reading 1 would go back as 1. Linux works by
inclusion (`xhci_port_state_to_neutral`): it writes back the read-only bits
and the bits that hold settings, and nothing else. The write now does the
same (`PORTSC_KEPT`), and `set` is held to the two resets
(`PORTSC_SETTABLE`), a list that grows with its callers. The review's third
point was one I had recorded as harmless: the write's own read made the
value written differ from the value the caller had decided on and logged.
The write now takes the caller's read, which also puts the read count back
where it was. The other four were records: the barrier check's docstring
claimed every routed write passed through both stores, the roadmap still
pointed at the deleted `portsc_preserve`, the handles are unforgeable only
outside `mod reg`, and one constant had been doing two jobs.

The old exclusion merge, put back as a mutation, now fails the asserts on
the case the review named, a reset in progress. `make test`,
`test-usb-hub` (19 ok, the same reset lines) and `test-el1-drop` were
green on both commits. On the wire the change is only a RsvdZ bit that
reads 1, now written 0; no capture has shown one, and no board round has
run it yet. Hans merged it as #209. DCBAAP and ERDP still share
`Whole64`, now an item of its own on the roadmap.
