# Ouroboros v0.12.0

Serve on another machine's network. [v0.11.0](v0.11.0.md) let a machine dial
*out* of another's NIC; this release adds the mirror — **dial-in**: a machine now
**accepts inbound** TCP connections on another machine's network presence. A
client that connects to machine A's address is answered by a program running on
a *different* machine. This completes the `/net/tcp` model symmetrically: active
open (dial-out) and passive open (dial-in).

This is pre-1.0 software: the syscall ABI and on-disk/on-wire formats are not yet
stable. Everything from [v0.11.0](v0.11.0.md) still works — the authenticated
export, dial-out, two-node disk sharing, the `/proc`/`/dev/cons`/`/net` file
servers, and `cpu` remote execution.

## What's new — `/net/tcp` dial-in

```
mount -n /net                 # bind THIS machine's /net
serve /net 9000 hi there      # answer clients that connect to US on :9000

mount -r 10.0.2.10:564 /mnt/a # mount machine A's export
serve /mnt/a/net 9000 hi there   # answer clients that connect to A on :9000
```

The last line makes a program *here* answer clients that connect to **machine A's
address** — A lends its ingress, this machine owns the service. It's the inverse
of `cpu A <server>` (which runs the server *on* A): here the server's state lives
where `serve` runs. The file model extends `/net/tcp`: write `announce <port>` to
a connection's `ctl`, then read `listen` to receive each accepted connection's
number, and read/write its `data` — all authenticated by the same cluster key as
any export access.

**How it works.** An accepted connection is just another `/net/tcp` connection
(its handle in the path, so still no per-client session state), so netd's existing
TCP machinery — buffers, retransmit, ACKing — services it unchanged; the new part
is the passive-open accept and the `listen` fan-out. As with everything in this
subsystem, netd's request handler only records intent while its event loop does
the actual TCP.

## Scope, honestly

Dial-in is a **TCP acceptor** with a **small fan-out** (a listener plus a couple
of concurrent connections) and stop-and-wait reliability — sized for small
request/response services, not a high-concurrency server. And note that
`cpu A <server>` already runs a server *on A's* CPU; dial-in is specifically for
when the service's state must live elsewhere while A only lends its ingress. It
completes the `/net/tcp` model rather than unblocking a waiting consumer.
Deliberately deferred: a persistent multi-client server loop, UDP, and richer
listener semantics.

## Running it

- **QEMU (single machine):** unzip `ouroboros-0.12.0-esp.img.zip` and boot
  `esp.img`. `mount -n /net` then `serve /net 9000 …` accepts on this machine's
  NIC.
- **QEMU (two-node cluster):** `make run-image-2vm-a` / `-b`; in B:
  `mount -r 10.0.2.10:564 /mnt/a`, then `serve /mnt/a/net 9000 …` to accept on A's
  NIC.
- **Parallels (Apple Silicon):** download `ouroboros-0.12.0-esp.dmg`, then wrap it
  into a Parallels-native `.hdd` locally:

  ```sh
  prl_disk_tool create --hdd esp.hdd --dmg "$(pwd)/ouroboros-0.12.0-esp.dmg"
  ```
