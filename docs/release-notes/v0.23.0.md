# Ouroboros v0.23.0

Ouroboros uses every core. The kernel starts each core the ACPI MADT lists,
brings it to EL1 on its own tables and gives it its own stack, timer and idle
loop. The shell and the servers stay on the boot core, and every program a
shell starts runs on another, so two programs run at once. One kernel lock
keeps one core at a time inside the kernel. It booted on QEMU, on the
Raspberry Pi 4 (2026-10-11) and on Parallels at four vCPUs (2026-10-12).

And C programs now run here as Unix commands. DevTools's C preprocessor runs
as `/bin/cpp`, and its output is byte for byte what the same `cpp` writes on
the Mac. DevTools's editor runs as `/bin/edit`, a full-screen program on the
framebuffer console.

Seventy-three pull requests since [v0.22.0](v0.22.0.md) (#209 to #281), over
eight days, 2026-10-05 to 2026-10-12.

**No wire flag day.** Nothing in the 9P framing or the cluster auth changed,
so a v0.22.0 node and a v0.23.0 node work together as before. **Two things an
installation sees:**

- **A command with more than 16 words is refused**, with `too many words`,
  and nothing runs. Before, the shell cut it at the sixteenth word without a
  message, so a program given twenty arguments ran with fifteen. A glob that
  expands past the kernel's 512-byte argument store is refused as
  `arguments too long`.
- **Ctrl+\ ends a foreground program in every mode.** A program can now take
  Ctrl+C as a key (raw keyboard mode, which an editor uses), so Ctrl+\ is the
  way out that no program can take away.

This is pre-1.0 software. ABI and on-disk/on-wire formats are not stable yet.

## Multi-core

- **Every core starts.** Each core in the MADT is started through PSCI
  `CPU_ON`, dropped to EL1 where the firmware handed it over at EL2 (the Pi
  4), and given its own GIC interface and timer. The boot log says
  `MADT: N cores`, then `smp: core N up at EL1` and `core N ticking` for each.
  A fault names its core (`EXCEPTION core=N`), and a secondary that faults
  in its own setup halts alone while the rest go on.
- **One kernel lock.** It is taken at every entry and released before the
  return, so the single-core reasoning every kernel static relied on became
  "the holder of the lock". `make check-statics`, run by `make test`, holds
  each of the kernel's 142 statics to a class in the plan's inventory.
- **Programs on every core.** Any core can interrupt another into the kernel
  with an SGI, on GICv2 and GICv3. An idle core wakes as soon as there is
  work for it, so a call to `fsd` from another core takes well under a
  millisecond. Ctrl+C and `kill` reach a program on another core at once.
- **A fair round per core.** Each core's tick keeps its own round, so every
  task a core may run is picked once a pass. Before, a spinning program and
  a typing shell on one core got `fsd` restarted as wedged, twice a boot.
- **Readable from the shell.** `cat /proc/cpus` prints how many cores take
  tasks; `ps` says `running on core N` for a task on a core, and
  `/proc/<n>/core` answers the same. `CORE_INFO` (syscall 75) and
  `/bin/COREPROBE` report it to a program.
- **The spawn staging has one owner.** Two tasks spawning at once used to
  interleave their chunks, and one started the other's image. A second
  stager is now refused with `SPAWN_ERR_STAGING_BUSY`, and the owner's
  `SPAWN`, exit or kill releases it.
- **A pipeline stage never runs before it may write.** `SPAWN` grants a child
  its stdout target in the same step, where the shell used to delegate each
  link after starting every stage, and a stage that wrote first lost its
  line. A program that ends without sending end-of-stream now sends it on
  exit, so `touch f | wc` no longer leaves `wc` waiting.

`make test-smp` boots `-smp 4` on EL1 and EL2 handoffs and both GIC versions,
and `-smp 1`, and fails a boot in which any server is restarted. `SMP=4` boots
any QEMU rig on four cores.

## C programs as Unix commands

The C-hosting plan (`docs/roadmap/roadmap-c-hosting.md`), all eight steps:

- `main(argc, argv)` gets its arguments, and `environ` the shell's
  environment, so `getenv` answers what `set` made.
- Every failure in the C file layer sets `errno` with its POSIX name.
- `stat`, `lstat`, `fstat` (which had written the file size into the wrong
  fields), `unlink`, `rmdir`, `rename` (with `EXDEV` across mounts) and
  `remove`.
- `gettimeofday` and `clock_gettime`, from the time since boot: there is no
  wall clock yet, so `time()` says 1970 plus uptime.
- The C headers are on the disk, under `/include` and `/include/clang`.
- `/bin/cpp`, DevTools's preprocessor, with those paths built in.

On FAT32 a name now keeps its case: `touch foo.txt` no longer lists as
`FOO.TXT`. `fsd` reads and writes the case flags macOS uses for a lowercase
8.3 name.

## A full-screen editor on the console

Every item DevTools asked for so Edit could run here:

- **Cursor addressing** on the framebuffer console: `CSI H`, `K` and `J` with
  their parameters, reverse video, and a late wrap so the bottom right cell
  can be written without scrolling.
- **The arrow, navigation and function keys** on the USB keyboard, and Tab
  and Escape, which sent nothing before. Every keyboard reader goes through
  one filter (the `keyseq` crate), so an arrow is never typed as `[A`.
- **The screen size**, by `ioctl(fd, TIOCGWINSZ, ...)` in C and
  `ulib::screen_size` in Rust; `more` pages by the real height.
- **Ctrl+C as a key**, through `tcsetattr` or the new `KBD_MODE` (70), with
  Ctrl+\ as the way out.
- **`poll`** on the keyboard with a timeout, blocked in the kernel to a
  tick's precision (about 20 ms), with no spinning.
- **Keys typed while a program is busy are kept**, in a 64-byte kernel queue
  that keeps every key whole. `TCSAFLUSH` discards them.
- **A cursor**, a steady inverted cell, hidden and shown by `CSI ? 25 l` and
  `h`. A killed program no longer leaves the screen inverted or the cursor
  hidden; `clear` restores both after a program that exited that way.
- `/bin/edit`, DevTools's Edit, built from its own tree.

## Fixed in the kernel and the servers

- **A task's FP/SIMD registers survive the kernel.** The kernel saved only
  `x0`-`x30`, on the old reasoning that nothing used vector registers.
  Everything did, the kernel's own `memcpy` included, so a value live across
  a syscall or a task switch could come back changed. Every resumable path
  now saves `q0`-`q31`, `FPCR` and `FPSR`. `make test-fpsimd`.
- **A call cut short by Ctrl+C no longer answers the next one.** A reply now
  names the call it answers (`SENDER_CALL`, 74, and `MSG_REPLY`, 73), and the
  kernel delivers it only while the caller is still in that call.
- **A large file no longer gets `fsd` restarted part way through.** `cp` of a
  758 KB file stopped near 170 KB with `server slot 2 wedged`. A FAT-sector
  cache and a free-cluster hint keep each write's cost flat.
- **A partition is mounted once, and `unmount` clears every disk mount**, so
  `erase`, `partition` and `format` run after it again.
- **Every program gets a 1 MiB heap, zeroed.** Up from 256 KiB, and a program
  can no longer read what the last one left in its region.

## Smaller things

- Reading a per-task store (`GET_ENV` and four more) accepts any buffer size.
- A rig refuses an image built from other sources: every image carries the
  git tree id it was built from (`\EFI\ORBS\SRCID.TXT`).
- PORTSC is a register type of its own in the xHCI driver.
- `make test` is at 203 host tests.

## Known on hardware

- **Parallels:** keys are lost while the USB stick is passed through to the
  VM, and the console server clears the kernel's boot lines before they can
  be read. Both are on the roadmap.
- **The kernel lock's cost and the FP/SIMD save** are measured on QEMU only.
- **Still not on the Pi:** networking (no NIC driver) and the SD card as a
  runtime disk (a USB stick is the disk).

## What is in a release

- `ouroboros-0.23.0-esp.img.zip`: the raw MBR+FAT32 disk image. Boot it under
  QEMU or any UEFI-AArch64 VM.
- `ouroboros-0.23.0-esp.dmg`: self-contained, for Parallels on Apple Silicon.
  Wrap it locally with:

  ```sh
  prl_disk_tool create --hdd esp.hdd --dmg <path>/ouroboros-0.23.0-esp.dmg
  ```

- `SHA256SUMS` for both.

For a Raspberry Pi 4, build from the tag and stage a card and a stick with
`make sdcard` and `make stick`, as `docs/testing/testing-pi4.md` section 4
describes; the release images are not a Pi card.

Networking, and therefore the entire cluster surface, is QEMU-only. Neither
Parallels nor the Raspberry Pi exposes a NIC this kernel can drive yet.
