# Ouroboros v0.20.0

A C program can open, read and write a file on another machine through a real
file handle; a nested shell keeps the keyboard through the commands it runs and
survives a stray Ctrl+C; and `netd` stops blocking its own event loop for
remote work, so a mount, a fid verb and a `cpu` run all proceed while the
server keeps serving everything else.

Thirty-two pull requests since [v0.19.0](v0.19.0.md). Three arcs and a long
tail: the fid verbs reaching the export and the held client sessions behind
them, the keyboard-ownership chain with the kernel primitives a review of it
demanded, and an asynchronous remote mount taken through all three of its
planned steps in a single day.

**No wire flag day.** The auth frame is untouched (`AUTHNP03`), so a v0.19.0
node and a v0.20.0 node authenticate and serve each other normally.

**But upgrade both nodes of a cluster together anyway, for two reasons.**

The first is the reserved error band. `FS_ERR_MIN` moved from `MAX-39` to
`MAX-43` to make room for `FS_ERR_BUSY` (`MAX-40`, "out of room, retry later")
and the C-facing task codes. A v0.19.0 client that receives one of the new
codes from a v0.20.0 export reads it as a *success* with an absurd byte count
rather than as an error. As with every floor move, this is invisible until it
is not.

The second is new in this release: a v0.19.0 export does not serve the fid
verbs on a session the way a v0.20.0 client expects, and a v0.20.0 client now
routes every C file handle that way. Mixed pairs will work for path-based
operations and fail for a C `open()` across the link.

This is pre-1.0 software. ABI and on-disk/on-wire formats are not stable yet.

## Syscall ABI changes, for anyone building against `syscall-abi`

- **The error floor moved** to `u64::MAX - 43`, as above. `libc/include/sys.h`
  mirrors it and names the task error codes, plus `NO_FS` and `FS_ERR_BUSY`,
  behind one shared `ouro_fs_strerror`. A C `read()` against a downed remote
  peer now meets `NO_FS` rather than a bare `-1`.
- **`MSG_SEND` accepts a packed task identity** in place of a slot number. Any
  destination at or above `1 << TASK_ID_SLOT_BITS` is the word `SENDER_TASK`
  answers, resolved through the occupant check and refused once that slot has
  been recycled. A server that replies *later* than the handler which received
  the call, which is what a parked request is, must reply this way. Replying by
  slot would complete a stranger's call with another caller's bytes.
- **`fg` (syscall 20) takes a `foreground` argument** and refuses a caller that
  does not currently own the keyboard. The argument selects whether Ctrl+C
  terminates the task (a foreground command) or detaches it back to its parent
  (a handed-over session).
- **An IRQ taken at EL1 halts with `vector=5`** rather than resuming. The
  kernel never runs at EL1 with interrupts unmasked, so that vector is a broken
  invariant rather than a resumable path.
- **A staging call is bounded by its own published maximum**, not by the
  blanket 512-byte pointer cap. `ENV_STAGE` advertised 2048 and enforced 512,
  which silently cost a spawned command its entire environment; argv (512), cwd
  (128) and namespace (256) were unaffected because their own limits sit at or
  under the old cap. Containment in the caller's own loaded region is unchanged
  and is the check that carries the safety.
- **The default per-task stack is 56 KB** (`STACK_PAGES` 10 to 14), grown three
  times for room on `netd`'s deep `serve` frame.

## A C program reaches a file on another machine

`open`, `pread`, `pwrite`, `fstat` and `clunk` now work against a remote mount,
not only a local one. The far export's fid is a number that lives on one TCP
connection and dies with it, so `netd` holds a **session** per `(endpoint,
user)` open across the separate verbs of a handle's life. `fsd` binds each fid
to its owning user and *keeps* it when a co-tenant is refused, rather than
dropping a handle someone else still holds.

The witnesses are C programs rather than shell commands, because only the C
path uses file handles: `cbig` reads a file larger than one chunk across the
link and byte-compares it against a local copy, and `cwrite` writes a pattern
through a remote handle and reads it back. Both run on the two-node ext2 rig,
and `cwrite` doubles as the permission control, since ext2 is the only format
here that records a mode for `fsd` to enforce.

## The keyboard follows a chain

A nested shell handed the keyboard with `fg` keeps it across the commands it
runs, and ownership reverts to whoever held it when the handover happened
rather than always to the boot shell. Ctrl+C is marked by task **generation**,
so a slot recycled mid-keystroke is not killed by a stale mark. A task reads
the keyboard only while it owns it. `fg` onto a task already in the chain no
longer builds a cycle.

A stray Ctrl+C at a nested prompt used to throw the session away, with its
login and working directory. It now **detaches** that session back to its
parent, which `fg` can resume; a foreground command its parent is waiting on is
still terminated. `make test-keyboard-chain` drives the whole chain.

## The remote mount goes asynchronous, all three steps

`netd` used to block its entire event loop for every remote round trip. While
it waited, the export served nothing, a `cpu` run made no progress, and a
second client simply had to be turned away. All three of the plan's steps
landed:

- **Path verbs** park on a connection the event loop drives, and the reply is
  delivered later to the caller's task *identity*.
- **Fid verbs** park on the held session, which stays open between verbs. When
  no session exists yet the park is two-phase, because the far export serves one
  framed request per session and the two cannot be pipelined.
- **The `cpu` run** parks the same way, its output drained into the pending
  buffer as it arrives and delivered on the peer's FIN.

With nothing blocking, the re-entrant drain and its by-sender refusal are gone
entirely, along with `tcp_run` and `pump_conns`.

**This fixed a live break, not just a latency problem.** A `cpu` child reading
the caller's files back through `/host`, the full Plan 9 `cpu` model, faulted
`netd` at its guard page and triggered a supervisor restart on *every*
attempt. It was measured against the previous tree with a control the day step
3 landed. Nothing had reported it because no rig ever exercised a `/host` read;
one does now.

## Smaller things

The syscall reference documents all 60 syscalls the kernel dispatches, having
described 46 of them and deferred the rest to the source. Two of its rows
stated a privilege model stricter than the kernel's, and one of those wrong
claims was inherited from the ABI's own doc comment. A zero-count `NP_PREAD`
answers `0`, the POSIX shape, instead of an error. A re-entrant remote request
is no longer able to overflow the guard page, because the path it overflowed
has been deleted.

## What is in a release

- `ouroboros-0.20.0-esp.img.zip`: the raw MBR+FAT32 disk image. Boot it under
  QEMU or any UEFI-AArch64 VM.
- `ouroboros-0.20.0-esp.dmg`: self-contained, for Parallels on Apple Silicon.
  Wrap it locally with:

  ```sh
  prl_disk_tool create --hdd esp.hdd --dmg <path>/ouroboros-0.20.0-esp.dmg
  ```

- `SHA256SUMS` for both.

Networking, and therefore the entire cluster surface, is QEMU-only. Neither
Parallels nor the Raspberry Pi target exposes a NIC this kernel can drive yet.
