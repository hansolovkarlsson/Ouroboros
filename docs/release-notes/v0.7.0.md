# Ouroboros v0.7.0

A shared disk. This release lands **Phase 2** of the distributed-cluster
direction ([`docs/roadmap-cluster.md`](../roadmap-cluster.md)): where
[v0.6.0](v0.6.0.md) let one machine **read** another's filesystem over 9P/TCP,
v0.7.0 lets it **write** — machine B creates and edits files on machine A's disk,
and A sees them on its own storage. This is **the milestone that answers the
years-long question — can several computers share resources as one system? — with
a yes you can act on:** two Ouroboros machines, one reading *and writing* the
other's disk over a protocol written from scratch.

This is pre-1.0 software: the syscall ABI and on-disk/on-wire formats are not yet
stable. Everything from [v0.6.x](v0.6.0.md) still works — the shell, `/bin`,
FAT32/exFAT/ext2 read-write, per-task namespaces + `bind` + multi-mount, the
network stack, remote read-mounts, USB on real Parallels hardware — this release
makes the remote mount **writable**.

## What's new in Phase 2

**Write over the network.** The export gateway was read-only; it now relays the
mutate verbs to the local filesystem server, so a remote mount is fully
read-write. Against `/mnt/a` (another machine's disk) all of these now work:

```
mkdir /mnt/a/reports
write /mnt/a/reports/note.txt hello from over here
cp /BIN/LS /mnt/a/ls.copy        # streamed in chunks over the wire
touch  /  rm  /  mv  ...
```

and the far machine sees every change on its own disk. Large writes are streamed
a chunk per round trip (there is no shared memory across machines, so file data
travels inline, bounded), and every `/bin` writer — `cp`, `writeat`, the shell's
`write`, `>>` redirection — works unchanged over a remote mount.

**Semantics, stated honestly: single-writer, clean-disconnect.** One machine
writes a given remote tree at a time, by convention — there is **no distributed
lock** (a later phase). A single writer never tears (the filesystem server
serializes all disk access through one task). If the peer drops, the next remote
op **fails cleanly** — a distinct error, the mount goes stale, nothing is
half-applied at your end, no hang, no corruption of the far disk. **Concurrent
multi-writer coherence is explicitly out of scope** for this release.

## How it was proven

Two Ouroboros VMs on a shared virtual link (`make run-image-2vm-a` /
`run-image-2vm-b`): from B, `mkdir`/`write`/`cat`-back and `cp /BIN/LS
/mnt/a/ls.copy` (a 17 KB file, streamed as 34 chunked round trips); then A,
reading its *own* disk, sees the new directory, the copy, and the note's exact
text. **Byte-exactness confirmed by a foreign observer** — mounting A's disk image
on macOS, the copied file is `cmp`-identical to the original, byte for byte.
Clean-disconnect verified by killing machine A mid-session: B's next operation
returns a clean error and B stays responsive. **Zero exception-trace aborts** on
both nodes. (A robustness fix the two-node link forced along the way: the client
now retransmits its connection SYN, so a dropped first packet no longer fails an
operation.)

## Scope, honestly

Phase 2 is **read + write, trusted-LAN, single-writer**. Deliberately deferred:

- **Authentication** (a hardening phase): an export still serves any peer that
  connects — trusted-LAN first, loudly documented.
- **Concurrent multi-writer coherence** (the hard CAP problem): single-writer is
  the contract; simultaneous writers to one tree are not made coherent.
- **`/net` and `/dev` as remotely-mountable files** (Phase 3), and **remote
  execution** (Phase 4).

## Running it

Identical to previous releases for a single machine; the cluster needs two.

- **QEMU (single machine):** unzip `ouroboros-0.7.0-esp.img.zip` and boot
  `esp.img` (see the Makefile's `run-image` target).
- **QEMU (two-node cluster):** `make run-image-2vm-a` in one terminal (machine A,
  start it first), `make run-image-2vm-b` in another (machine B), then in B:
  `mount -r 10.0.2.10:564 /mnt/a`, and now `mkdir`/`write`/`cp` onto A's disk.
- **Parallels (Apple Silicon):** download `ouroboros-0.7.0-esp.dmg`, then wrap it
  into a Parallels-native `.hdd` locally:

  ```sh
  prl_disk_tool create --hdd esp.hdd \
      --dmg "$(pwd)/ouroboros-0.7.0-esp.dmg"
  ```
