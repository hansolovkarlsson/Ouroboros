# Ouroboros v0.4.0

The first cut release. Ouroboros is an ARM64 (aarch64) microkernel written
in Rust, UEFI-native, developed against QEMU and tested on real Parallels
Desktop hardware on Apple Silicon. This release bundles everything built to
date — four major arcs — as one bootable image.

This is pre-1.0 software: the syscall ABI and on-disk formats are not yet
stable, and are expected to change.

## What's in the box

**Boot & kernel core.** UEFI-native boot (no separate bootloader), ACPI/MADT
device discovery, GICv2/GICv3 interrupt controllers, the ARM generic timer,
AArch64 exception vectors, an MMU with per-task translation tables, and a
round-robin preemptive scheduler over EL0 tasks with MMU-enforced isolation.

**Userland & IPC.** A relocating ELF/PIE loader; programs loaded from disk,
not compiled in. A capability-based IPC model (who-may-call-whom), grant/
safecopy bulk transfer, program-to-program pipes, a stack guard page, and a
supervisor that restarts crashed or wedged servers.

**Servers (drivers in userland).**
- `fsd` — the filesystem server: **FAT32, exFAT, and ext2, all read-write**,
  behind one FS-agnostic protocol, plus GPT/MBR partition discovery.
- `cond` — the console server: byte-stream (UART) and framebuffer (glyph
  rendering) backends.
- `netd` — the network server: a full **TCP/IP stack** (ARP/IPv4/ICMP/UDP/
  DNS/TCP) with a concurrent static-file HTTP server — congestion control
  (Reno), SACK, adaptive RTO, fast retransmit.

**Shell & `/bin`.** A userland shell with a real `/bin` of standalone
programs found via `PATH`, argv, a shell environment with `$VAR` expansion,
output redirection (`>`/`>>`), and multi-stage pipelines (`a | b | c`).

**Disk management.** From inside the guest: `erase`, `partition` (MBR),
and `format` (mkfs for **all three** filesystems — FAT32, exFAT, ext2),
each validated against foreign checkers (macOS `fsck_exfat`/`fsck_msdos`,
`e2fsck`/`debugfs`).

**Hardware.** A from-scratch xHCI (USB3) driver with a real HID keyboard and
USB mass storage — confirmed working on real Parallels hardware, including
the keyboard↔storage bus-contention fix (endpoint-reset BOT recovery + a
minimum-settle port scan).

## Running it

- **QEMU:** unzip `ouroboros-0.4.0-esp.img.zip` and boot `esp.img` as a
  drive under `qemu-system-aarch64` with AArch64 UEFI firmware (see the
  Makefile's `run-image` target for the exact invocation).
- **Parallels (Apple Silicon):** download `ouroboros-0.4.0-esp.dmg` (a
  self-contained compressed disk image), then wrap it into a
  Parallels-native `.hdd` locally and attach that as the VM's hard disk:

  ```sh
  prl_disk_tool create --hdd esp.hdd \
      --dmg "$(pwd)/ouroboros-0.4.0-esp.dmg"
  ```

  (The `.hdd` bundle references the `.dmg` by absolute path, which is why
  the portable artifact is the `.dmg` and the wrap is done on your machine.)

See [`docs/manual.md`](../manual.md) for the full run/build/shell tour.

## Known limitations

Pre-alpha kernel: no unit test suite (it proves it boots and runs), two-task
minimum scheduler roots, and userland syscall buffers capped at 512 B. The
network stack and `/bin` surface are primarily QEMU-verified; USB keyboard +
mass storage are the hardware-confirmed Parallels path. See
[`docs/roadmap.md`](../roadmap.md) for what's next, and
[`docs/roadmap-cluster.md`](../roadmap-cluster.md) for the long-term
distributed-cluster direction.
