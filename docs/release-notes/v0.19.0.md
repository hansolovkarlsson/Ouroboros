# Ouroboros v0.19.0

A network program works inside a pipeline, a nested shell can pipe at all, every
task has an identity a recycled slot cannot inherit, and a C program can open a
file on another machine.

Thirty pull requests since [v0.18.1](v0.18.1.md). Half of them are kernel and
shell work on one theme, capability delegation, where a thirty-line fix on
09-06 turned into four new kernel primitives because each pre-existing gap it
uncovered needed one. The other half is the C arc reaching remote mounts, the
9P wire growing an honest "not implemented" answer, an MIT licence, and a
reorganization of `docs/` that moved paths a reader may have bookmarked.

**No wire flag day.** The auth frame is untouched (`AUTHNP03`), so a v0.18.1
node and a v0.19.0 node authenticate and serve each other normally. **One
cross-node caveat, though:** the reserved error band gained a code,
`FS_ERR_NO_SUCH_VERB`, and that moved the error floor from `MAX-38` to
`MAX-39`. A v0.18.1 client that receives that one code from a v0.19.0 export
reads it as a *success* with an absurd byte count rather than as an error. No
v0.18.1 program sends a verb a v0.19.0 export refuses, so this does not occur in
practice, but upgrade both nodes of a cluster together anyway. This is pre-1.0
software: ABI and on-disk/on-wire formats are not yet stable.

## Syscall ABI changes, for anyone building against `syscall-abi`

- **Two new syscalls**, `SENDER_TASK` (67) and `TASK_IDENTITY` (68), return a
  packed task identity: a boot-wide generation in the high bits and the slot in
  the low eight. A slot number is a position; this names the occupant.
- **`DELEGATE` answers `TASK_ERR_NO_SUCH_TASK`** when either end of the link is
  not a live task, and `MSG_ERR_DENIED` only for a refusal the caller cannot fix
  by retrying. It used to fold both into a denial.
- **The delegation rule changed.** A task may delegate to its own direct child a
  send right toward any task it can itself reach. The old "delegator statically
  holds the target" rule is gone, subsumed by that one. A spawner and its child
  are granted each other at spawn, so a nested shell captures and redirects the
  way the boot shell does.
- **Grants accumulate.** A task's delegations are a set, so a pipeline stage can
  hold its consumer link and its network right at once. There is still no
  revoke short of task death.
- **The error floor moved** to `u64::MAX - 39`, as above. `libc/include/sys.h`
  mirrors it, and `check-wire-constants` now reads that header too.

## Network programs inside pipelines, and four kernel primitives behind them

`cat /mnt/a/HELLO.TXT | wc` failed with `cat: failed`. So did `ping 10.0.2.2 |
wc`, and any other network-using program placed in a pipeline or run under
`exec`, while the same command unpiped worked. The record blamed a supervisor
timeout; the host peer's request log showed the request never left the guest.
The shell granted a spawned program its network right on one spawn path out of
three, and the kernel held one delegated right per task, so a pipeline stage
given its consumer link lost its network right, silently.

The grant now happens in the one function every spawn path goes through, and a
task's grants are a set. The review of that fix found a security regression the
widening had opened, in a file the diff never touched: any program could grant a
*server* a send right. The grantee must now be a spawnable slot.

Each of the gaps that review uncovered turned out to need a kernel primitive
rather than a patch:

- **A failed pipeline no longer eats a task slot.** A stage that had already
  exited was a zombie the kernel refused to kill, so every "abandon this
  pipeline" path leaked one of five slots. Five mistyped `grep`s and the shell
  could run no `/bin` program at all. Eight teardown paths now go through one
  kill-and-reap helper.
- **The kernel says which end of a link died.** The shell used to guess from a
  state read after the fact and print `pipe: could not authorize the stream`
  over a producer's own error message. `DELEGATE` now answers with the reason,
  and a silent producer's non-zero exit is reported instead of vanishing.
- **A grant aimed at a supervised server survives its restart.** A program
  alive across a `netd` restart lost its network right for the rest of its
  life. Nothing but the same server ever returns to a protected slot, so the
  grant is kept. Checked by wedging `netd` on cue under a long `ping`: six
  failures out of six before, replies resuming after.
- **Every task has an identity.** `netd` remembered its remote-exec child and
  each run's owner by slot number, and a slot is recycled the moment its task
  is reaped, so a `ping` landing in a reaped child's slot was routed to a
  stranger's connection and never answered. The kernel now issues a generation
  per occupant and captures it with the credential it already binds at send
  time. The review caught a regression in the first version: messages with no
  identity, the supervisor's own health ping among them, matched `netd`'s
  "no child" sentinel, and an idle client got `netd` restarted every ping
  interval.
- **A nested shell can pipe.** Delegation consulted only the static capability
  table, so a spawned `SH.BIN` could authorize no link and hand out no network
  right: every pipeline under it failed and its whole subtree was netless.
  Rights now flow one step down, from a task to its own direct children. A
  consequence, stated rather than hidden: `SPAWN` is ungated, so any task may
  spawn a child and pass it what it holds. That grants nothing the task could
  not have relayed itself. Gating `SPAWN` is recorded as its own decision.

## The C library reaches a remote mount

```
$ mount -r 10.0.2.2:5641 /mnt/a
$ cremote
/EFI/ORBS/INIT.CFG: fd=3 size=16 first=\EFI\ORBS\SH.BIN
/mnt/a/HELLO.TXT: fd=3 size=1960 first=line 000: hello from the host 9P server over TCP
```

A C `open("/mnt/a/F")` used to ask the local filesystem server about a path only
the network server knows, and never left the machine. The C library now
resolves the namespace through `nsresolve`, a Rust static library wrapping the
same resolver `ulib` and `netd` use, rather than a third hand-written copy, and
sends each request to whichever server the path lives on. Reads, `fstat` and
`close` work on a remote file; a remote `write()` is refused rather than
silently dropped, until the export learns the write verb.

`open()` still returns `-1` for everything, with `ouro_last_fs_status()` beside
it as the way to ask why. That is deliberately not `errno`. Two bugs in that
status were found by an audit and closed in the last PR of this release: the
client-side code sat just below the error floor, so the program written to read
it said "no error recorded", and the status was never cleared on success as its
comment claimed. `cremote` now checks both.

Along the way: `fsd`'s `NP_OPEN` handed back a valid fid for a read-only open of
a file that did not exist, and created a file for `O_TRUNC` without `O_CREAT`.
Both refuse now.

## A refused 9P verb says so

Both 9P peers answered a verb they had no arm for with the generic error, which
every client renders as "no such file or directory": a message about a path,
for a request whose path was fine. That had already cost a debugging session
and was about to cost another. `FS_ERR_NO_SUCH_VERB` is the answer now, each
server logs the verb number, and the host test peer serves the read-capable fid
verbs and checks them by round trip.

Two more changes to the 9P clients, both groundwork for a persistent export
session that is planned but not built: the reply's length is on the wire, and
both clients now read it instead of waiting for the server's FIN; and `fsd`'s
permission check refuses by default for any verb without an explicit arm, with a
compile-time tripwire that fires when a verb is added.

## Housekeeping a reader will notice

- **An MIT licence.** The repository had been public without one, which means
  all rights reserved.
- **`docs/` reorganized**, so bookmarked paths moved: the twenty-nine
  postmortems into `docs/postmortems/`, the cluster and fid-verb plans into
  `docs/roadmap/`, the four testing guides into `docs/testing/`, the research
  notes into `docs/research/`, and the journal became `docs/work-journal/`,
  one file per day. `ROADMAP.md`, `CHANGELOG.md` and `manual.md` stay at the
  root; `docs/roadmap.md` is now `docs/ROADMAP.md`.
- **The published site is checked against its sources** on every `make test`.
  Four abridged pages (changelog, roadmap, shell commands, processes) were
  deleted in favour of links to the markdown, which removes their drift for
  good. Three markdown sources turned out to be behind the code while clearing
  that backlog, and were fixed at the source.
- `make all` exists, and `make test` now runs the wire-constant check across
  Rust, the two C headers and the two Python peers, plus the host 9P peer's
  verb-dispatch self-test.

## Known, on the roadmap's ledger

- A foregrounded nested shell loses the keyboard after every command. Type
  `fg 6` before each command until it is fixed.
- A producer that exits without ending its stream wedges the pipeline:
  `ls -? | wc` never returns a prompt, and `touch f | wc` either wedges or is
  torn down with its consumer.
- The nested shell's network grant has no failure signal: the one `DELEGATE`
  in the shell that discards its result.

## Getting it

`ouroboros-0.19.0-esp.img.zip` boots under QEMU or any UEFI-AArch64 VM;
`ouroboros-0.19.0-esp.dmg` is for Parallels on Apple Silicon. Wrap it locally
with:

```sh
prl_disk_tool create --hdd esp.hdd --dmg <path>/ouroboros-0.19.0-esp.dmg
```

Verify against `SHA256SUMS`. See [`docs/manual.md`](../manual.md) to drive it,
and [`docs/testing/testing-qemu.md`](../testing/testing-qemu.md) for the QEMU
and two-node cluster rigs.
