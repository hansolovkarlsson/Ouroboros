# Ouroboros v0.8.0

Everything is a file — even another machine's. This release lands **Phase 3** of
the distributed-cluster direction ([`docs/roadmap-cluster.md`](../roadmap-cluster.md)):
three system resources become **file trees**, each readable (or writable) from the
machine that owns it *and*, over the [v0.6/v0.7](v0.7.0.md) 9P/TCP transport, from
another machine across the network:

- **`/proc`** — the process table. `ls /mnt/a/proc` on one machine lists **another
  machine's** live tasks; `cat /mnt/a/proc/2/state` reads its filesystem server's
  scheduler state.
- **`/dev/cons`** — the console, as a writable file. `write /mnt/a/dev/cons …`
  prints on **another machine's** screen (remote console).
- **`/net`** — the network identity. `cat /mnt/a/net/ip` reads **another machine's**
  IPv4 address; `/net/mac` its MAC.

It's the Plan 9 idea — *a resource is a file, a remote resource is a remote file* —
made concrete across a from-scratch protocol.

This is pre-1.0 software: the syscall ABI and on-disk/on-wire formats are not yet
stable. Everything from [v0.7.x](v0.7.0.md) still works — the shell, `/bin`,
FAT32/exFAT/ext2 read-write, per-task namespaces + `bind` + multi-mount, the
network stack, two-node read/write disk sharing, USB on real Parallels hardware.

## What's new in Phase 3

**Three new file servers, each local + remote.** Bind one into your namespace and
read it like any directory:

```
mount -p /proc            # the process table
ls /proc                  #   -> 0/ 1/ 2/ ... one dir per task
cat /proc/2/state         #   -> runnable | blocked | zombie | unused

mount -c /dev/cons        # the console, as a writable file
echo hello > /dev/cons    #   -> "hello" renders on this screen

mount -n /net             # the network identity
cat /net/ip               #   -> this machine's IPv4
cat /net/mac              #   -> this machine's MAC
```

And across the network, against a remote mount (no bind needed on your side):

```
mount -r 10.0.2.10:564 /mnt/a
ls  /mnt/a/proc           # machine A's tasks
cat /mnt/a/net/ip         # machine A's address
write /mnt/a/dev/cons hi  # prints "hi" on machine A's screen
```

Each server rides the machinery already there: `/proc` is a synthetic arm of the
filesystem server (the first non-disk filesystem it drives); `/dev/cons` routes to
the console server; `/net` is served by the network server itself. All read-only
except `/dev/cons` (write-only).

## How it was proven

On QEMU and between two Ouroboros VMs on a shared virtual link
(`make run-image-2vm-a`/`-b`): each resource read (or written) locally, then the
same from the *other* machine — B lists A's tasks, reads A's address, and prints on
A's console. Verified with true scheduler/NIC values (fsd `runnable`, netd
`blocked`, A's derived `10.0.2.10`), and **zero exception-trace aborts** on both
nodes throughout.

## Scope, honestly

Phase 3 is **resources as files, remotely readable**. Deliberately deferred:

- **`/net` is network *identity*** (address/MAC), not yet Plan 9's full `/net/tcp`
  connection files — dialing *out* through another machine's NIC is a larger, later
  surface.
- **A fully namespace-aware export.** The three resources are exported by explicit
  path prefix; a general export that resolves incoming paths through a composed
  per-export namespace (retiring the prefix special-cases) is the next structural
  step, now that there are three consumers.
- **Authentication** stays deferred — trusted-LAN, loudly documented. `/proc` and
  `/net` are read-only; `/dev/cons` writes to a screen.
- **Remote execution** (Plan 9's `cpu` model — run a program *there* with its
  namespace imported from *here*) is Phase 4.

## Running it

Identical to previous releases for a single machine; the cluster needs two.

- **QEMU (single machine):** unzip `ouroboros-0.8.0-esp.img.zip` and boot
  `esp.img` (see the Makefile's `run-image` target). Try `mount -p /proc; ls /proc`.
- **QEMU (two-node cluster):** `make run-image-2vm-a` in one terminal (machine A,
  start it first), `make run-image-2vm-b` in another, then in B: `mount -r
  10.0.2.10:564 /mnt/a`, and `ls /mnt/a/proc`, `cat /mnt/a/net/ip`, `write
  /mnt/a/dev/cons hi`.
- **Parallels (Apple Silicon):** download `ouroboros-0.8.0-esp.dmg`, then wrap it
  into a Parallels-native `.hdd` locally:

  ```sh
  prl_disk_tool create --hdd esp.hdd \
      --dmg "$(pwd)/ouroboros-0.8.0-esp.dmg"
  ```
