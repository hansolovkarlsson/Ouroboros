# Ouroboros v0.14.0

Two things land together: `cpu` remote-command output stops being capped at a
single IPC message, and the `/bin` pipeline-filter set doubles. Neither changes
the cluster wire format or the syscall ABI — everything from
[v0.13.0](v0.13.0.md) still works (mutual export auth, dial-out/dial-in, two-node
disk sharing, the `/proc`/`/dev/cons`/`/net` file servers, `cpu` remote
execution). This is pre-1.0 software: ABI and on-disk/on-wire formats are not yet
stable.

## What's new — `cpu` output past one message (chunked pull)

`cpu <host:port> <cmd>` used to hand the shell exactly one `MSG_CALL` reply, so a
command's output was silently truncated at **768 bytes** — `cat` a real file or
`ls` a busy directory over `cpu` and you saw only the first message's worth.

The shell now **pulls the output in chunks**. The capability model chose the
design: `netd` doesn't hold `TO_SHELL`, so it can't *push* a stream — it can only
answer via the one-shot reply exemption. So `handle_run` collects the run into a
`PendingRun` buffer and returns the first 768-byte chunk; the shell pulls the rest
with a new `NETOP_RUN_MORE` op until an empty reply signals end of stream. An
owner check means only the task that issued the run can pull its output, and only
one run is pending at a time.

**Scope, honest:** this lifts the cap from 768 bytes to ~2 KB (the remote's send
buffer) — enough for realistic command output — but it is still **bounded**,
because `netd` collects the whole run before the shell pulls it. Truly unbounded
streaming (the remote sending as the child produces) is a documented later arc in
[`roadmap-cluster.md`](../roadmap-cluster.md). See
[`cpu-streaming-postmortem.md`](../cpu-streaming-postmortem.md) for the design and
the guard-page trap dodged on purpose.

## What's new — four more `/bin` pipeline filters

The line-filter set (`upper`/`grep`/`wc`/`head`) gains four classic Unix filters,
each a standalone `programs/textutils/` crate over `ulib` in the same shape
(stdin = `pipe_recv`, stdout = `write_out`), chainable as pipeline middle stages:

- **`tail [N]`** — the last N lines (default 10), the complement of `head`. It
  can't stop early, so it keeps the newest lines in a fixed ring (cap 64) and
  flushes at EOF.
- **`nl`** — numbers every line, right-aligned 6-column count + tab (`cat -n`).
- **`rev`** — reverses each line's byte order, trailing newline kept last.
- **`uniq`** — collapses runs of *adjacent* identical lines (Unix semantics;
  pairs with a future `sort`).

All four are bounded to a 256-byte line buffer with no heap, and every binary
links with **zero relocations** (fully position-independent — the recurring PIE
trap avoided by construction). The workspace is now 36 crates.

## Running it

Identical to previous releases.

- **QEMU (single machine):** unzip `ouroboros-0.14.0-esp.img.zip` and boot
  `esp.img`. Try the new filters:
  `cat /TEST.TXT | uniq | wc`, `ls | nl`, `echo hi mom | rev`.
- **QEMU (two-node cluster):** `make run-image-2vm-a` / `-b`, then in B:
  `mount -r 10.0.2.10:564 /mnt/a`, and `cpu 10.0.2.10:564 cat /host/BIG.TXT` now
  returns the full output, not just the first 768 bytes.
- **Parallels (Apple Silicon):** download `ouroboros-0.14.0-esp.dmg`, then wrap it
  into a Parallels-native `.hdd` locally:

  ```sh
  prl_disk_tool create --hdd esp.hdd --dmg "$(pwd)/ouroboros-0.14.0-esp.dmg"
  ```
