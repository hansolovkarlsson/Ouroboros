# Ouroboros v0.11.0

Use another machine's network. The cluster could already share a disk, `/proc`,
the console, network *identity*, and remote execution; the one resource it
couldn't share was the **active side of the network** — dialing out to reach the
world. This release adds it: a machine now opens a TCP connection **out of another
machine's NIC**, exposed as Plan 9's `/net/tcp` connection files.

This is pre-1.0 software: the syscall ABI and on-disk/on-wire formats are not yet
stable. Everything from [v0.10.0](v0.10.0.md) still works — the authenticated
export, two-node read/write disk sharing, the `/proc`/`/dev/cons`/`/net` file
servers, and `cpu` remote execution.

## What's new — `/net/tcp` dial-out

```
mount -n /net                              # bind THIS machine's /net
dial /net 93.184.216.34 80 GET / HTTP/1.0  # dial out of OUR nic

mount -r 10.0.2.10:564 /mnt/a              # mount machine A's export
dial /mnt/a/net 93.184.216.34 80 GET / HTTP/1.0   # dial out of A's nic
```

The only thing that changes is the base path: `/net` is your network,
`/mnt/a/net` is A's — so the last line reaches the outside *through A's
connection*, authenticated by the [v0.10.0](v0.10.0.md) cluster key like any
export access. It's the Plan 9 model: read `/net/tcp/clone` for a connection
number `N`, write `connect <ip>!<port>` to `/net/tcp/N/ctl`, then read/write
`/net/tcp/N/data`.

**How it works.** The connection handle lives in the *path* (`/net/tcp/N/…`), so a
stateful, long-lived connection needs no per-client session state — `netd` keeps a
bounded connection table, and every op is an ordinary path-based verb naming a
slot. `netd`'s request handler only records intent (allocate, connect, queue data,
drain data); **all the actual TCP happens in its event loop** — the same "a
network server must never block its own loop" discipline the rest of the stack
holds to. Routing reuses the existing namespace resolver, so dialing out of A's
NIC is *literally just* the path `/mnt/a/net/tcp/…`.

## Scope, honestly

`/net/tcp` is a **TCP client**, with **stop-and-wait** reliability — sized for the
small request/response transactions it targets, not bulk transfer. And note that
`cpu A fetch example.com` *already* dials out through A's network for the
run-a-program case; `/net/tcp`'s distinct value is a **raw** connection you drive
byte-by-byte, with no matching program needed on A, composed as files. Deliberately
deferred: dialing *in* (inbound `listen`/`accept` through another machine), UDP,
and flow/congestion control beyond a single-segment window.

## Running it

- **QEMU (single machine):** unzip `ouroboros-0.11.0-esp.img.zip` and boot
  `esp.img`. `mount -n /net` then `dial /net <ip> <port> …` dials out of this
  machine's NIC.
- **QEMU (two-node cluster):** `make run-image-2vm-a` / `-b`; in B:
  `mount -r 10.0.2.10:564 /mnt/a`, then `dial /mnt/a/net <ip> <port> …` to dial out
  of A's NIC.
- **Parallels (Apple Silicon):** download `ouroboros-0.11.0-esp.dmg`, then wrap it
  into a Parallels-native `.hdd` locally:

  ```sh
  prl_disk_tool create --hdd esp.hdd --dmg "$(pwd)/ouroboros-0.11.0-esp.dmg"
  ```
