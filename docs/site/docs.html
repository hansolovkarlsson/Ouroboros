Postmortems

Every real bug that mattered, written up in full — symptom, root cause, how it was actually confirmed, and the generalizable lesson. In chronological order, each usable on its own.

Part 1 · Boot bring-up

From "it doesn't boot" to a real console

Exception vectors, the MMU switch, GIC/timer bring-up, the EL0/syscall boundary, and a console-discovery saga that killed three mechanisms and one whole driver before finding the one that worked on real hardware.

 Part 2 · Shell & filesystem

From a bare prompt to a real, disk-backed OS

A relocation bug found twice before its real shape was understood, a hang with zero diagnostic output, a disk that lied about its own filesystem format, and the write-support arc built on top.

 Part 3 · xHCI keyboard

Getting a USB keyboard working on Parallels

Seven real, confirmed hardware bugs bringing keyboard input to the kernel — a PCI Command register bit, a real UEFI firmware panic, a page-table assumption, a silently-dropped USB request class, a driver reading the wrong device, and two found weeks later, one of them by a user, not a script.

 Part 4 · USB storage

Giving Parallels a disk

Proving the hypervisor exposes no storage controller at all, USB passthrough that routes devices by speed and attaches them after your boot scan already ran, a mid-transfer keystroke that would have permanently killed the keyboard, and SCSI Unit Attention found by a hot-plug test.

 Retrospective · a different era

Enforce the isolation, rebuild the data flow

A design-led day, not a bug hunt: MMU-enforced per-task isolation and fault containment, then rebuilding every cheap data path enforcement broke — grant/safecopy IPC, a FAT32 offset-write, and the one works-on-QEMU-fails-on-silicon reversal.
