# Source map

Every source file in the tree, annotated: what it does, and — more usefully —
the constraint that made it the shape it is. `kernel/`, all of `programs/`, the
shared library crates, `libc/`, and `scripts/`.

This is a *map*, not the reference. For any one subsystem the deeper sources are
better: each file carries its own `//!` module doc — though see the caveat at
the end of this file — the design rationale is in
[`architecture.md`](architecture.md) and [`processes.md`](processes.md), the
milestone record in [`CHANGELOG.md`](CHANGELOG.md), and the traps already hit in
the postmortems ([`README.md`](README.md) indexes them). What this file is *for*
is the question those can't answer: **where does a given thing live, and what
else will I have to touch.**

This map used to live inline in `CLAUDE.md`'s `## Structure` section, and was
moved here on 2026-09-03, verbatim. `CLAUDE.md` is read at the start of *every*
session; this is 90KB of detail that matters only once you know which subsystem
you are in, and it was being paid for unconditionally. `CLAUDE.md` keeps the
tree skeleton — one line per file, enough to find the right one — and defers
here.

Some annotations carry cross-references worded "see … above". Those pointed at
milestone sections that have since moved to [`CHANGELOG.md`](CHANGELOG.md) and
the postmortems; look there for the full write-up.

  src/acpi.rs        console UART discovery via ACPI RSDP -> XSDT -> SPCR (works on QEMU, dead end on Parallels), plus the shared find_table(rsdp, signature) walk madt.rs also uses

  src/console.rs     global console handle (Console enum: Pl011 | Uart16550 | Virtio | Framebuffer), shared between main() and the exception handler
  src/framebuffer.rs GOP (EFI_GRAPHICS_OUTPUT_PROTOCOL) discovery: resolution/stride/pixel format + framebuffer physical base/size - the real lead for Parallels, see "GOP framebuffer console" above
  src/font.rs        embedded public-domain 8x8 bitmap font (dhepper/font8x8), printable ASCII 0x20-0x7E only
  src/fbconsole.rs   text console rendered directly into the GOP framebuffer: glyph drawing, cursor, ptr::copy-based scroll - write-only, no ANSI parsing; now the kernel's *emergency/boot* console only (steady-state userland rendering moved to the cond server - see "Driver isolation, part 3"), see "GOP framebuffer console" above
  src/fbdev.rs       dumb framebuffer primitives for the console server: plot a run of glyph bitmaps (FB_BLIT), scroll (FB_SCROLL), clear (FB_CLEAR), all gated to CON_TASK - the pixel plumbing cond drives while it owns the font/cursor/wrap/scroll/ANSI logic, see "Driver isolation, part 3"
  src/exceptions.rs  AArch64 exception vector table (VBAR_EL1) + fault reporting; SVC path (slot 8/"3:") saves x9 to a scratch stack slot before the EC check clobbers it (see "A real relocating loader" above) and saves/restores SP_EL0 at Context's real offset alongside ELR/SPSR, passing dispatch() the frame pointer itself (see "Blocking primitives" above); slot 8's non-SVC fall-through is the resumable EL0-fault path ("4:"/rust_el0_fault_handler) - kills just the faulting task, and restarts it via supervisor::restart if it was a supervised server (fsd/cond), see "EL0 fault isolation" and "Server supervision + heartbeat" above; rust_irq_handler routes the timer PPI to tasks::on_tick and the NIC receive SPI to tasks::on_net_irq (IRQ-driven RX, see docs/CHANGELOG.md's "Network stack, Stage 4k")
  src/mmu.rs         per-task translation-table views (one L0/L1/L2/L3 per scheduler slot; identity-mapped kernel/device shared, EL0 access to each task's own region only - enforced isolation, see "Per-task page tables" above), up to MAX_EL0_REGIONS (10, kept equal to tasks::NUM_TASKS; the table pools are [const {..}; N] so they auto-scale) tasks/views, activate_task switches TTBR0+TLBI per context switch, an optional framebuffer device-block fallback, and (since "Dynamic task creation") a stashed memory map/extra-device list plus rebuild_with_el0_regions so install_identity_map can be called a second time at runtime - see "Dynamic task creation and exec()" above
  src/gic.rs         version-dispatching facade over gicv2.rs/gicv3.rs, selected by madt.rs's real discovery - see "MADT/GICv3" above
  src/gicv2.rs       GICv2 backend (distributor + memory-mapped CPU interface), addresses now passed in from madt::GicInfo instead of hardcoded; enable_interrupt routes an SPI (>=32, e.g. the NIC) to CPU 0 via GICD_ITARGETSR, not just PPIs
  src/gicv3.rs       GICv3 backend (redistributor wake/discovery, ICC_* system-register CPU interface; enable_interrupt handles SPIs via the distributor - GICD_ISENABLER/IROUTER/IGROUPR - as well as PPIs via the redistributor) - confirmed working on QEMU and real Parallels hardware, see "MADT/GICv3" above
  src/timer.rs       ARM generic timer (non-secure EL1 physical timer, PPI 14 / GIC INTID 30), TICK_INTERVAL_MS
  src/loader.rs      reads INIT.CFG + a program off the ESP during boot services (plus the filesystem server \EFI\ORBS\FSD.BIN and console server \EFI\ORBS\COND.BIN, each registered with supervisor::register for crash/wedge recovery), into 2MB-aligned EL0-accessible regions, real ELF64 parsing + R_AARCH64_RELATIVE relocation processing - see "A real relocating loader" above and docs/processes.md; elf_region_size/populate_region split so the same parsing/loading logic is reusable from the runtime spawn path and supervisor restarts too, see "Dynamic task creation and exec()" and "Server supervision + heartbeat" above
  src/supervisor.rs  server supervision registry: keeps each supervised server's boot ELF image and restarts it on a crash (generic fault hook) or a wedge (on_tick's heartbeat), with a per-boot restart cap - the generalized replacement for syscall.rs's old fsd-only restart_fsd/FSD_IMAGE, now covering fsd AND cond, see "Server supervision + heartbeat" above
  src/syscall.rs     svc syscall dispatch table (print/double/report/try_read_char/putc/get_ticks/read_char/spawn/exit/task_state/task_name/kill/fg/wait/mount/msg_send/msg_recv/msg_try_recv/block_info/block_read/block_write/msg_call/spawn_stage/grant/safecopy/.../delegate, and the argv syscalls args_stage/get_argc/get_arg (spawned programs receive arguments - see "Standalone binaries, Stage 1"); task_name (54) is the read-only argv[0]-of-any-task companion to task_state that lets `ps` show process names (boot tasks named by the loader via tasks::set_name/server_name); task_exit_code (55) peeks a zombie's exit status WITHOUT reaping it (unlike wait) so `ps` shows `exited (code N)`; power (56) is machine power control (mode off/halt) backed by power.rs - shutdown/halt builtins; yield (57) is a cooperative give-up-the-slice (tasks::yield_current_and_switch, switches to another runnable task preferring real work over idle) used by ulib::pipe_out on a full consumer mailbox so a producer hands the CPU to the consumer instead of busy-spinning until the next tick; env_stage (58)/get_envc (59)/get_env (60) are the environment-export ABI (the argv-shaped twin): env_stage LATCHES an env blob (same [count][len][NAME=VALUE] encoding as argv) for the next SPAWN - SPAWN's four args are full so there's no length arg, it rides PENDING_ENV_LEN - which the kernel attaches per-task (tasks::set_env/env_blob), and the child reads it back via get_envc/get_env (ulib::env_count/env_at/getenv); note get_env's out-capacity is bounded by MAX_USER_LEN (512) like every user pointer, so read one entry at a time (ENV_MAX=2048 is the whole-blob store size, not a read cap); set_id (61)/get_id (62) are the USER IDENTITY primitive (the login arc): set_id sets the calling task's packed (gid<<32)|uid (tasks::IDS, mirroring STDOUT_TARGET), allowed if the caller is root OR the target equals its SAVED identity (tasks::SAVED_IDS - POSIX saved-set-uid): root drops to a user, and a non-root task may only RESTORE to its saved (the shell's logout path), else SET_ID_DENIED (no escalation); apply_id saves the old current as the new saved on every change; get_id reads any task's packed identity; SET_ID's arg2/arg3 additionally carry the SUPPLEMENTARY GROUP LIST as a (pointer, count) pair, so identity and membership change together and a 0/0 does NOT mean 'leave the groups alone' - it means CLEAR them (the group half is root-only even for a caller allowed the identity half, since membership is a privilege grant; a non-root caller may pass only an empty list); get_groups (64) reads a task's list back, MAX_SUPP_GROUPS=8; sender_id (65)/sender_groups (66) are what a SERVER authorizing a request must use instead of GET_ID/GET_GROUPS of the sender slot - the kernel binds the sender's credential when the message is SENT, because GET_ID(sender) answers "who occupies slot N NOW" and a caller can MSG_SEND (non-blocking), EXIT, and have its slot reaped and re-spawned before the server drains its mailbox (refusing a DEAD slot never closed that - a RECYCLED slot is alive and the message carries a bare u8 with no generation); groups travel WITH the identity since SET_ID's group half exists so the two can't be set out of step; only an UNFILTERED receive updates the capture, so a server's own MSG_CALL reply can't overwrite what it is about to authorize against (fsd logs to cond through exactly such a call), and KERNEL_SENDER's health ping carries no credential so anything authorizing it fails closed; a child INHERITS its parent's CURRENT identity at SPAWN with saved:=that current (NOT the parent's saved - so a user's children can never restore root, the escalation guard), reset to root on death - the KERNEL owns the binding as the unforgeable root of trust (only it knows an IPC sender), names/passwords/policy stay userland (reverses the roadmap's tentative "userland" lean - see gap-analysis.md §6); backs /bin/id, the root-only `su` builtin, and the shell's login/logout (drop to a user, restore root on logout), and the prompt shows #/$; gaps at 5 and 7-14 - the old fs_* syscalls moved to the fsd server's FSOP_* protocol) plus the block-device cell (the kernel's entire remaining storage role) and in_caller_region validation - grant/safecopy are the enforced bulk-transfer primitive (see "Grant/safecopy IPC"), delegate (41) is runtime capability delegation of the IPC send-mask (see "Runtime capability delegation" above)
  src/tasks.rs       NUM_TASKS (11) task slots (task 0 = loaded program, task 1 = idle, task 2 = filesystem server, task 3 = console server, task 4 = network server, task 5 = account server, slots 6-10 spawn/exit-cycled - FIRST_SPAWNABLE=6, five spawnable (the fourth server was added by RAISING NUM_TASKS, not by eating a spawnable slot - that pool is where a pipeline's stages come from); per-task arrays are [const {..}; NUM_TASKS] so they auto-scale, and the caps u32 keeps resource caps at bits 16+ clear of the low-NUM_TASKS-bit send-mask) + the round-robin scheduler over Runnable/Blocked/Unused/Zombie task state (block_current_and_switch, exit_current_and_switch, yield_current_and_switch (the YIELD syscall - stays Runnable, switches via next_runnable_skip_idle), on_tick's wake-check + the supervisor heartbeat, tasks::spawn, allocate_runtime_region/free_runtime_region, mailboxes with direct delivery + sender-filtered receive, WaitReason::NetInput (with an optional deadline, so NET_WAIT can time out - the network server's RTO timer) + the async-receive wake for the network server, per-task grant slots + safecopy for the bulk-transfer primitive, per-slot capability send-mask + per-task runtime delegation for who-may-call-whom, per-task argv store set at spawn/cleared on death for the argv ABI, the matching per-task ENV store (set_env/env_blob/clear_env - the environment a child inherits, latched by ENV_STAGE and read via GET_ENVC/GET_ENV), and the per-task USER IDENTITY (IDS: a packed (gid<<32)|uid per slot, default root, inherited at spawn via inherit_id, reset on death; plus SAVED_IDS - the POSIX saved-set-uid a task may restore to via SET_ID even once non-root, apply_id saving old-current-as-saved on each change, inherit_id setting a child's saved to its OWN current so it can't restore root - the login arc: SET_ID root-gated-or-restore-saved, read by GET_ID; plus GROUPS - the per-task supplementary gid list (set_groups/groups_of, MAX_SUPP_GROUPS=8), inherited at spawn and cleared on death like the identity it travels with, which fsd consults so a file's group triad applies on a PRIMARY or any SUPPLEMENTARY match); plus SENDER_CREDS - the credential of the sender of the last message each task received, CAPTURED AT SEND (into the queued Message, or straight into the receiver's cell on the direct-delivery path) because GET_ID(sender) answers "who occupies slot N NOW" and a server authorizing a request is asking who occupied it THEN - a caller can MSG_SEND, EXIT, and have its slot re-spawned before the server drains its mailbox; only an UNFILTERED receive updates it, so a server's own MSG_CALL reply can't overwrite what it is about to authorize against, and a message the kernel sends on nobody's behalf (KERNEL_SENDER) carries none, read via SENDER_ID/SENDER_GROUPS) - confirmed working, see "Blocking primitives", "Dynamic task creation and exec()", "Task destruction", "Driver isolation" parts 1/2/3, "Grant/safecopy IPC", "The capability model", "Runtime capability delegation", and "Server supervision + heartbeat" above
  src/virtio_mmio.rs virtio-mmio transport: 32-slot device discovery, modern (non-legacy) register layout, addresses confirmed via devicetree dump
  src/block.rs       BlockDevice enum (Virtio | UsbMsd) - the block-device abstraction fat32.rs sits on, see "USB mass storage" above
  src/usb_msd.rs     USB mass storage: Bulk-Only Transport + SCSI (INQUIRY/READ CAPACITY/READ(10)/WRITE(10)) over xhci.rs's bulk endpoints - Parallels' first working disk, see "USB mass storage" above. Now with BOT error recovery (bot_command retries with xhci::storage_reset_endpoint between attempts) - the real-Parallels "Mode A" fix where keyboard/storage contention stalled a bulk endpoint that then stayed halted forever; see docs/CHANGELOG.md's "xHCI keyboard <-> USB-storage contention"
  src/virtio_blk.rs  runtime virtio-blk driver: feature negotiation, one virtqueue, synchronous polling sector reads and writes - phase 3a (reads)/phase 4 (writes), confirmed working, see above
  src/virtio_console.rs  transmit-only virtio-console driver over the same transport - device discovery, feature negotiation, transmitq0 - confirmed working on QEMU; confirmed *not* what Parallels' serial port actually is, see "virtio-console" above
  src/virtio_rng.rs  virtio-rng (entropy source) driver over the same transport - the SIMPLEST virtio device here (one virtqueue, no config space, no device-specific features), modeled on virtio_console.rs; the one structural difference is a device-WRITABLE descriptor (VIRTQ_DESC_F_WRITE), so the used ring's `len` says how many bytes the device actually wrote (the spec allows fewer than asked - fill() returns that count, next_u64() reports None on a short read rather than padding). Backs the RANDOM syscall (63) behind syscall.rs's RNG cell; installed by main.rs::init_entropy only AFTER a successful test draw. ABSENT on most platforms and that's a supported case (only QEMU with `-device virtio-rng-device`; Parallels/Pi have no virtio-mmio) - userland degrades LOUDLY via accounts::salt_from's `strong` flag
  src/virtio_net.rs  virtio-net driver over the same transport: receiveq (pre-posted buffers) + transmitq, VIRTIO_F_VERSION_1/VIRTIO_NET_F_MAC negotiation, the 12-byte virtio_net_hdr, send_frame/poll_frame moving opaque Ethernet frames, plus IRQ-driven receive (has_frame/intid/ack_interrupt: the RX queue's GIC SPI wakes netd via exceptions.rs + tasks::on_net_irq - Stage 4k; TX interrupts suppressed, transmit still polls) - the DMA-owning kernel half of the network stack, QEMU-only (gated like virtio-blk; Parallels' virtio-net is PCI). See docs/CHANGELOG.md's "Network stack" entries and main.rs's init_net
  src/xhci.rs        from-scratch xHCI (USB3 host controller) driver: command/event rings, multi-device port scan (every connected device enumerated, its interfaces logged, and kept concurrently addressed - up to 4, see "xHCI multi-device support" above), per-device EP0 rings/output contexts, and a real interrupt endpoint for HID keyboard reports - confirmed working end to end with a real keyboard on real Parallels hardware, see "USB HID keyboard driver" above and docs/xhci-keyboard-postmortem.md. The boot port scan is minimum-settle + debounce (SCAN_MIN_SETTLE_MS/SCAN_DEBOUNCE_MS/SCAN_SETTLE_CAP_MS), NOT "break on first connected device" - the real-Parallels "Mode B" fix where a fast SuperSpeed stick won the enumeration race and the slower synthetic keyboard was missed for the whole boot; also storage_reset_endpoint (Reset Endpoint + Set TR Dequeue) for usb_msd's BOT recovery ("Mode A"). See docs/CHANGELOG.md's "xHCI keyboard <-> USB-storage contention"

programs/            ALL userland programs live here (aarch64-unknown-none, loaded from disk, not compiled into the kernel), grouped by role under category dirs; kernel + the shared libs (ulib, syscall-abi, ninep-abi, accounts, regex, ed25519, clusterkeys) stay at the repo root. Crate paths below are shown in full (programs/<category>/<crate>/). See the workspace note after this block for the move rationale.
  linker.ld          the shared self-relocating (PIE) linker script EVERY program uses: entry at offset 0, .rela.dyn/.dynsym/.dynamic/.data.rel.ro, AND now .data/.bss (the loader's .data/.bss milestone - the old ASSERT(SIZEOF(.data/.bss)==0) guards are gone, so programs may have mutable statics/globals; C programs need this). Referenced by .cargo/config.toml as -Tprograms/linker.ld (path relative to the workspace root, not any one crate); see "A real relocating loader" above and docs/processes.md

programs/shell/      userland default shell - loaded from disk (not compiled into the kernel)
  src/login.rs       the LOGIN gate (users arc, step 2): login() runs at the top of every session - prompts username + password (echo off), reads /etc/passwd via the shell's ONE account-file reader (main.rs::read_account_file - chunked at FS_DATA_MAX=512 with a bounded NO_FS retry for the boot mount race; login/su/id all share it since 2026-08-29), verifies SHA-256(salt||password) constant-time against /etc/shadow (the secret lookup STREAMS one line rather than holding the file - a whole-file read reported 0 on overflow, which for shadow means 'no secret' and locked EVERY account out, root included, at ~23 accounts), and SET_IDs the shell down to the user - identity AND the supplementary group list in ONE call, so a session never carries the previous user's groups; logout restores root (saved-uid) and re-prompts. No /etc/passwd -> root-session fallback. Byte-only parsing (PIE-safe)
  src/main.rs        line editor + command dispatch (help/cd/bind/mount/unmount/erase/partition/format/exec/cpu/exit/logout/shutdown/halt/ps/kill/fg/wait/env/set/unset/su builtins - a deliberately MINIMAL set: only shell-state (cd/bind/env/set/unset/su - su changes the shell's OWN task identity via SET_ID, ROOT-ONLY so a logged-in user can't escalate, and print_prompt shows #/$ from GET_ID), login/logout (the outer main loop gates each session on login::login then runs the interactive loop until Env.logout, set by exit/logout - the shell never EXITs, it's task 0), job control (ps/kill/fg/wait/exec), disk mgmt that must run unmounted (mount/erase/partition/format), power that must run unmounted (shutdown/halt), remote-exec (cpu), and help/exit. pwd/write/more/less/send/recv/selftest were all externalized to /bin (more/less could move once the keyboard arc let a /bin program read keys) (shutdown/poweroff + halt call the POWER syscall - builtins not /bin so they work with no disk mounted, like erase/partition/format; more/less is the pager - a builtin because a pager must read the keyboard while running and only task 0 owns the keyboard, so it can't be a spawned /bin program; `more <file>` or `<cmd> | more`, captured into the heap then page_content pages it) - bare `mount` now *lists* what's mounted via FSOP_MOUNT_INFO (format + partition LBA + capacity + a flags word whose MOUNT_FLAG_ENFORCES_MODES bit says whether the mounted fs can enforce permissions - login's warning reads that bit instead of string-matching the format name), `mount -a` performs the old mount action, `mount <n> <path>` multi-mounts a local partition (Phase 0), `mount -r <host:port> <path>` remote-mounts another machine's 9P export into this namespace (cluster Phase 1c - a path under it resolves to a NETOP_RMOUNT round trip via netd), `mount -p <path>` binds the synthetic /proc (cluster Phase 3 - the process table as files, at the reserved NS_PROC_TREE), `mount -c <path>` binds the console as a writable file (cluster Phase 3 /dev/cons - a write routes to CON_TASK/cond via the NS_CON_TREE sentinel; `write /mnt/a/dev/cons ...` prints on another machine's screen), `mount -n <path>` binds netd's synthetic /net (cluster Phase 3 - the machine's network identity ip/mac as read-only files via the NS_NET_TREE sentinel; local reads are direct NP calls to NET_TASK, remote `cat /mnt/a/net/ip` reads another machine's address), `unmount` drops it via FSOP_UNMOUNT (milestone 1); `erase disk` (FSOP_ERASE) and `partition [fat32|exfat|ext2]` (FSOP_PARTITION, MBR) prepare a blank disk (milestone 2), `format [fat32|exfat|ext2]` (FSOP_FORMAT, mkfs - FAT32 + exFAT + ext2, all three) lays a filesystem into the partition (milestone 3, complete) - these three MUST be builtins not /bin programs (they run when nothing is mounted, exactly when /bin can't be read to load a program); the disk-management arc, see docs/roadmap.md - the whole filesystem command surface (echo/uptime/clear/ls/cat/mkdir/rmdir/touch/rm/cp/mv/writeat) AND the network commands (ping/resolve/fetch) are externalized to /bin now, Stage 4; the netd ones reach the network server via TO_NET the shell delegates at spawn (delegate_net in run_path_command), plus filename WILDCARDS (glob `*`/`?` expanded against the fs in run_line via expand_globs, bash-style no-match-stays-literal) and TAB COMPLETION (complete_word: complete the last word as a filename - single match fills in, several extend to the common prefix and list) - both written in BYTES not &str (slicing a &str by a runtime index pulls in unlinkable core::fmt, R_AARCH64_ABS64 - the same PIE limit selftest guards, so glob/completion helpers hand-roll rfind/strip/case-fold on &[u8]); plus `> file`/`>> file` output redirection and multi-stage `a | b | c` pipelines (split_pipeline/cmd_pipeline: N program stages spawned right-to-left, each producer->consumer link a DELEGATE, argv + PATH per stage; a SINGLE builtin may sit at ANY position - cmd_pipeline classifies stages and, for a builtin at index k>0, drains stages[..k] as a program pipeline (drain_program_output, no size cap) then runs stages[k..] via run_head_pipeline with the builtin as head, since a builtin runs in the shell + reads no stdin so it can only be a source; run_head_pipeline takes a PipeSink of Console|Redirect|Drain unifying the three destinations; 2+ builtins refused; see docs/roadmap.md's multi-stage-pipeline arc) - and the two now COMPOSE: `a | b > file`/`>> file` points the last stage's stdout at the shell (self_task) instead of CON_TASK so run_line's redirect capture (capture_program_output -> finish_redirect) writes it to the file, the same path a single `cmd > file` uses (redirect parsed FIRST in run_line, so any `|` stays in the cmd part); an unknown command is then looked up as a program on PATH via run_path_command - /bin by bare name, foreground/reaped - see "Standalone binaries, Stage 2"; plus env/set/unset and $VAR expansion over a stack-local env store, with PATH a real variable driving the lookup - see "Standalone binaries, Stage 3"; that env is now EXPORTED to every spawned command (Env::serialize -> ENV_STAGE in spawn_path, threaded through run_found_command/spawn_stage/cmd_exec), so a child reads it via ulib::getenv/env_at and `/bin/printenv` prints it), running as real EL0 userland code, built for real relocation (relocation-model=pic, --release only) - main loop blocks on read_char (syscall 15) instead of busy-polling, see "Blocking primitives" above; see docs/processes.md

programs/servers/fsd/    fifth userland program: THE FILESYSTEM SERVER (driver isolation part 2) - owns the FAT32 engine, speaks the FSOP_* protocol to clients over IPC (including the bulk FSOP_READ_BULK/FSOP_WRITE_BULK ops that move file data via grant/safecopy - see "Grant/safecopy IPC" above), and is the only task the BLOCK_* syscalls accept; boot-loaded into protected task slot 2, see "Driver isolation, part 2" above
  src/main.rs        the request loop: recv -> decode FsRequest -> PERMISSION-CHECK (check_access) -> dispatch to the mounted vfs::Filesystem -> reply one u64; it lives in main's stack frame (no static state in userland). PERMISSION ENFORCEMENT (users arc step 3): before running any NP_* file verb, check_access compares the RESOLVED caller (see effective_caller) against the target's owner/mode (mode_allows: root bypasses, then owner->group->other rwx triad; reads need R on the target, writes W on the file-or-parent, create/delete/rename W on the parent, chmod owner-only, chown root-only), returning FS_ERR_PERM on refusal. ext2-only (stat returns mode:None for FAT/exFAT/proc; since 2026-09-02 check_access asks models_modes ONCE at the top and returns true for the whole request, which is what NP_STAT/NP_CHMOD/NP_CHOWN used to miss by calling ancestors_searchable directly); ancestor-directory search-bit (x) traversal is deferred (only the object + its parent are checked); remote-via-netd is now PER-USER (2026-08-31): the caller is resolved ONCE per request by effective_caller(op, sender, req) - for any sender but NET_TASK that is the kernel-bound credential (SENDER_ID/SENDER_GROUPS) and the request's a3 word is IGNORED, so no ordinary task can claim an identity; for NET_TASK it IS a3 - either NP_ID_FIRST_PARTY (netd's own business, authorized as netd) or a packed proxy (uid,gid) - and a NET_TASK request that states NOTHING is REFUSED rather than falling back to netd's root, which was the hole. programs/servers/accountd/  THE ACCOUNT SERVER (users arc, the self-service tier) - boot-loaded into protected task slot 5 (ACCT_TASK), supervised, the FOURTH server (fsd/cond/netd/accountd - slot 5 is its task number, not an ordinal). WHY A SERVER AND NOT A SETUID BIT: /etc/shadow is 0600 root, which is the point, but that leaves a user unable to change their OWN password. Unix answers with a setuid passwd binary, and that answer CANNOT work here - the kernel does not read files, fsd does, so a /bin binary is read by the SHELL and handed to SPAWN, making "this binary is setuid" an assertion by a user-controlled task the kernel cannot verify (an escalation path straight through the component the capability model exists to distrust). A server inverts it: accountd never asks who a program CLAIMS to be, it asks the kernel who SENT the message and decides itself. Policy entire: root may set any account's password without the old one; anyone else may change only their own and must prove the current one. Every spawnable slot statically holds TO_ACCT, safe for the same reason every slot may call fsd - holding the right to ASK is not permission to SUCCEED, and the check is in the server; accountd holds no device capability at all, its privilege is policy not a resource. ONE op (ACCTOP_PASSWD); creating/deleting accounts stays with the root-only /bin tools, which need no privilege they don't already have. A ulib client (unlike the older servers that predate ulib and hand-roll their fsd calls), over the shared pure `accounts` crate - the "repoint, not a rewrite" the account-management arc predicted. The fussiness is load-bearing, not defensive: the PL011 the guest reads has NO RX FIFO, so a byte arriving while the guest isn't looking is GONE - hence one character at a time with a delay, and matching only output produced SINCE the last step (searching the whole buffer matches a PREVIOUS prompt and starts typing while the guest is still printing, silently eating the first characters so `cat /etc/shadow` arrives as `t /etc/shadow` and the test fails for a reason unrelated to the code). ## Where a new file goes

New userland programs slot into the matching `programs/<category>/` directory
(or a new category), depending on `syscall-abi` — and usually `ulib` — via the
`../../../` path their siblings use. Every userland crate is deliberately
excluded from the workspace's `default-members` (see the root `Cargo.toml`),
since they need a different `--target` than `kernel`.

`kernel` and the shared library crates (`ulib`, `syscall-abi`, `ninep-abi`,
`accounts`, `regex`, `ed25519`, `clusterkeys`) stay at the repository root.
